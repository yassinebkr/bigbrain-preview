## Release gates

Passing component tests establishes individual contracts. Release also requires
complete worker journeys and measured model-driven acceptance against requested
facts, qualifications and actually inspected citations.

1. **Inference boundary:** one scoped conversation binding, structured terminal
   response, observed native-call visibility, bounded interruption, explicit
   usage and no automatic provider fallback. Fresh and resumed bindings must be
   assessed separately. A requested raw-event flag alone proves configuration.
2. **Acquisition:** public HTTP observation, one bounded render upgrade when
   JavaScript is required, separate HTTP/render allowances, provenance hashes,
   no rendering of blocked/authenticated/rate-limited responses, bounded cleanup.
3. **Delivery:** at least one relevant inspected passage before a substantive
   conclusion, valid current citation identities, preserved source qualifications,
   useful partial findings and explicit essential unanswered obligations.
4. **Efficiency:** duration, logical model calls, native requests, input/output/
   cached tokens, unknown usage and acquisition requests are retained. The current
   90-second and 120,000-unit admission envelope are recorded. Reservation
   estimates can be exceeded remotely; monetary cost remains unknown where the
   provider supplies no prices.

Any critical provenance, permission or false-completion failure blocks release.
Source domains and repeated statements do not establish reliability independently.

## Offline journey matrix

`tests/test_research_journey_acceptance.py` exercises the authenticated production
worker using frozen HTTP responses and scripted model decisions. It covers:

- Static documentary delivery with the original operating qualification.
- Empty JavaScript document recovered within its original HTTP acquisition slot.
- Real Chromium execution through the guarded transport over offline routes.
- HTTP 401, 403 and 429; private-address rejection with no HTTP request.
- Disabled/unavailable rendering and explicit renderer failure.
- Invented citation rejection, terminal result uniqueness and bounded decisions.
- Four grouped HTTP attempts with a maximum of two render upgrades.
- Pending HTTP observations rendered after HTTP capacity is exhausted.
- Deadline interruption and renderer cleanup with an incomplete terminal result.

Existing suites separately cover changed observations, exact quotation anchoring,
versioned sources, duplicated origins, counterevidence, claim/coverage assessment,
conversation ownership, continuation, invalid structured decisions and cancellation.

Scripted decisions make these runtime journeys reproducible. They do not measure
the configured model's semantic accuracy. The real-browser test uses offline
fixtures; the installed-browser requirement must be visible as a skip when absent.

## Model-driven campaign

Before closure, evaluate a fixed heterogeneous set: versioned API behavior,
database concurrency, calibration/configuration documentation, JavaScript-heavy
hardware reference, copied claims/contradiction and blocked-access recovery.
Annotate the necessary passages, critical qualifications and acceptable partial
outcomes before running the candidate. Include held-out question reformulations
and at least two measured repetitions per case to expose model variance.

Audit every critical requested fact and its cited support, essential omissions,
unrelated assertions, language/version suitability and completion classification.
A partial finding can be useful; it must not be counted as full coverage.
Record the native tool-attempt count alongside logical calls to expose nested
agent loops. A deterministic fixture success cannot substitute for this gate.
Paid execution requires explicit authorization. No additional live campaign is
started by this document.

## Current Codex transport

The current fixed-scope delegation, compact generation variants, source index
and bounded validation feedback are documented in `RESEARCH_SCOPE_AND_ACTIONS.md`.

Research uses the client-owned decision tool described in
`RESEARCH_CODEX_BRIDGE.md`. The native thread submits an Action through
`bigbrain_submit_decision`; the client interrupts that native turn, waits for its
completion and validates the proposal before the research runtime performs I/O.
Collection and review have durable, role-scoped thread bindings. Existing native
tool guards, call bounds and deadlines remain enforced. Raw-event visibility on
resumed threads remains version-sensitive, and interrupted turns can lack usage
reports. Conservative admission units and measured tokens are recorded separately.

The Git browser journey in `RESEARCH_GIT_RECOVERY.md` exercises the React chat,
frontbrain, orchestrator, researcher, real public acquisition and page reload.
The heterogeneous campaign above remains the general reliability criterion.

Protocol reference: https://learn.chatgpt.com/docs/app-server . The installed
binary's generated experimental schema and TypeScript notification bindings were
also inspected. Raw-event controls remain version-sensitive.
